# The stable streams in C: 68× per thread, and LuaJIT builds disagree on `%.13f`

T-341 ported `pseudohash`, `pseudoseed`, LuaJIT's `math.random` (TW223) and the pool picks for skip tags, bosses, vouchers and the Soul's legendaries to C (`native/src/bhsim.c`, a Linux `.so` loaded through LuaJIT FFI). `rig/smoke.sh native_diff` runs 1,000,000 seeds (`seedfinder.worker.seed_at(0..999,999)`, Red Deck, stake 1, antes 1-8) through both the port and `bhcore.sim.predict` on 24 `love.thread` workers. It also runs 2 × 500 seeds on the main thread against the live prototypes (stake 1, and stake 8 with all_unlocked).

Result, 2026-09-23 (a 32-core desktop): **1,000,000 seeds, 0 differences**. The Lua walk (`state.fresh` + predict) runs at 1,117 seeds/s per thread and the C walk at 75,558 seeds/s per thread, so the port is **67.6× faster per thread**. Both walks plus the comparison took 38.9 s of wall time on 24 workers, about 44 s for the whole scenario. The Lua figure pays for `state.fresh` on every seed, the same cost the Finder pays, so the speedup applies to the Finder's workload too.

## Traps

- **`string.format('%.13f')` rounds half-way cases differently depending on the LuaJIT build.** LÖVE 11.5's LuaJIT (2.1.1700008891) rounds a tie away from zero. The system LuaJIT (2.1.1788856981) and glibc round it to even. The ties are exactly x = j/2^14 for odd j: `2^-14` formats as `0.0000610351563` in the game and `…562` on the host. The first rig run failed 4,096 of the 8,192 tie probes. The C side therefore takes the rule as a setting (`bh_set_round_ties`), and `native/lua/bhsim.lua` sets it from the running LuaJIT's own output. **Verified** in the rig and in `make -C native test`, which checks both rules. **UNVERIFIED**: which rule the Windows game's own `lua51.dll` uses (T-343 must probe it the same way at load time, never assume it). Also **UNVERIFIED**, but practically irrelevant: whether a stream ever lands exactly on a tie. It needs `(2.134453429141 + v·1.72431234) % 1` to have at most 14 fractional bits.
- **`tonumber(string.format('%.13f', x))` needs no string round trip.** Exact integer rounding of `x·10^13` (128-bit), followed by one IEEE division by `1e13`, gives the same double that `strtod`/`lj_strscan` return for that decimal. **Verified** on 208k values under the system LuaJIT and 28k in the game.
- **`pseudorandom_element` orders array pools by index and the boss table by key.** The boss table's values are use counts, not tables with `sort_id`, so it sorts with Lua's `<` (byte order). The C side receives the boss list pre-sorted with the same `<`. **Verified** (1M seeds).
- **With every legendary held, the Soul still draws.** `get_current_pool` falls back to the one-entry pool `{'j_joker'}`, and `pseudoseed('Joker4')` still advances. The legendary pool key has no ante (`Joker4`, resamples `Joker4_resample2`…), but the edition stream does (`edisou<ante>`). **Verified**: in the diff walk the Soul used in each ante is held afterwards, so antes 6-8 hit the fallback on every seed, and a mutation that skips the fallback draw fails the unit test.
- **`get_current_pool('Joker', nil, true, 'sou')` draws `rarity<ante>sou` even for a legendary** (common_events.lua:1968, where `_rarity or pseudorandom(...)` runs before the legendary override). No stable output reads that stream, so the port skips it. The glue builds the legendary mask with `get_current_pool('Joker', 4, true)` to avoid that draw. **Verified** by reading the code, and indirectly by the 1M diff. Only the legendary path may skip it. A second Soul in the same ante would advance `rarity<ante>sou` in the game but not in the port. No output reads that stream today, but T-342 must keep it in mind if a later draw ever shares the key (**UNVERIFIED** whether any does).
- **Exact doubles.** `pseudohash` is kept in Lua's evaluation order: `((1.1239285023/num)·byte·π + π·i) % 1`, where `% 1` is `a − floor(a)`. The build uses `-ffp-contract=off` and no fast-math. **UNVERIFIED** that an FMA-contracted build would actually differ, since the default x86-64 target has no FMA. It's a precaution for `-march=native` and mingw builds.
- **`math.random(n)` in LuaJIT 2.1 (non-DUALNUM) is `floor(r·n) + 1`**, where r is `(TW223 bits | 0x3ff…) − 1.0`, drawn after `randomseed(d)` runs 10 warm-up steps. **Verified** against both LuaJIT builds.
- **Pools come from the running game, not from the source.** Tags use vanilla `get_current_pool('Tag')` at each ante. That handles `min_ante` and the profile's `requires` discovery, which is why all_unlocked is a separate context. Vouchers use `get_current_pool('Voucher')`. `UNAVAILABLE` entries become a mask. The masks are static under a no-purchase walk. Buying a voucher (which changes `used_vouchers` and tier-2 `requires`) needs a context rebuilt from the new state. **Verified** for the fresh-run walk only.
- An all-empty pool comes back from `get_current_pool` as vanilla's one-entry fallback, which the glue maps to an all-zero mask. For a pool whose full list has exactly one entry, the two cases can't be told apart. No real pool is that small. **UNVERIFIED**, unreachable today.

## T-342: shops, packs and pack contents in C, 80× per thread

T-342 extends the port to the conditional streams: shop rows with rerolls, shop packs, pack contents (Arcana, Celestial, Spectral, Standard, Buffoon), the Charm and Ethereal tag packs, editions, stake stickers, the Soul and Black Hole gates, and `used_jokers` bookkeeping. The C side is `bh_shop_batch` in `native/src/bhsim.c`. It walks `predict.ante_walk` for antes 1..N under one skip/reroll policy. The glue is `bhsim.shop` / `shop_walk` / `shop_record` / `shop_diff` in `native/lua/bhsim.lua`. Every pool, mask, fallback, weight and size is read from the running game through vanilla `get_current_pool`, and nothing is hard-coded.

`rig/smoke.sh native_diff_shop`, result from 2026-09-23 (a 32-core desktop):

- **Golden seeds, main thread, live G.** The 10 golden_shop seeds (stakes 1 and 8) and the 4 golden_walk seeds ran under every skip policy × rerolls 0 and 2, antes 1-3. That is 112 walks, plus `predict.plan` on the 28 no-skip walks. **0 differences.** `STR_PACK(G.GAME)` is unchanged across the step.
- **200,000 seeds on 24 workers.** `worker.seed_at(0..199,999)` ran at stake 1 and at stake 8, so 400,000 walks, antes 1-3, with seed i under policy i % 8. **0 differences.** The Lua reference (`state.fresh` + 3 × `ante_walk`) runs at 406 walks/s per thread and the C walk at 32,593 walks/s per thread, so the port is **80.2× faster per thread**. Both walks plus the comparison took 44.3 s of wall time; the whole scenario takes about 49 s.

`make -C native test` adds five shop groups. They check the C walk against `bhcore.sim.predict.ante_walk`, loaded unmodified under the system luajit, on synthetic pools: locked and banned entries, a shared joker name, pool flags, a softlocked planet, tiny Soul and Black Hole pools, every booster kind, Illusion, Omen Globe, Telescope, stickers and `all_eternal`, a used Soul or Black Hole at the start, and the forced Buffoon given or banned.

### Traps

- **`get_current_pool('Joker', _rarity)` takes a rarity *roll*, not a rarity.** It computes `(roll > 0.95 and 3) or (roll > 0.7 and 2) or 1`, so passing `1` returns the rarity-3 pool. The glue asks with rolls 0, 0.8 and 1, and asserts that the returned key is `Joker<r><ante>`. **Verified**: the first version asked with 1/2/3, and the fallback probe got pool `Joker3` for all three. T-341's `get_current_pool('Joker', 4, true)` is unaffected, because `_legendary` overrides the roll.
- **`used_jokers` is written and cleared by name, not by key** (`Card:set_ability`, `Card:remove`). The C side keeps one used flag per name group. **Verified**: the synthetic pools contain two jokers named "Twin", and a mutation that keys the flag by center fails 4 of 5 shop groups.
- **The Enhanced pool is not culled by `used_jokers`.** Its branch in `get_current_pool` is `add = true` before the used check. The glue reads this off the game: it marks every key used and checks whether the pool still has entries. It does not hard-code the rule. **Verified** in the test, where an Enhanced center shares the "Twin" name.
- **Fallback keys come from the game too.** The glue bans every entry of a pool and reads back the one-entry fallback. Enhanced falls back to `j_joker`, vanilla's `else` branch. **Verified**: with only 4 live planets, a Jumbo Celestial pack's 5th card is the `c_pluto` fallback, thousands of times in the test.
- **`rarity<ante>sou`, the stream T-341 skips.** The shop and pack jokers draw `rarity<ante>sho` and `rarity<ante>buf`, never `…sou`. No stream this walk reads shares a key with the Soul's skipped draw. **Verified** by the key format in `create`/`get_current_pool` and by the 400k diff. It is still **UNVERIFIED** for a future walk that uses two Souls in one ante.
- **`G.P_CARDS` fronts are drawn in sorted-key order.** `pseudorandom_element` sorts a keyed table by key when its values have no `sort_id`, and P_CARDS values have none. **Verified**: a planted descending sort gives 1,364 golden differences.
- **Each resample key is its own stream.** `Joker1sho3_resample7` is a stream separate from `Joker1sho3`. The stream map went from 256 to 1024 slots and the key buffer from 48 to 64 bytes. On a full map the walk returns E_MAP rather than overflowing. **Verified**: T-341's `native_diff` is still 1,000,000 seeds, 0 differences with the larger map.
- **The golden seeds alone are not enough.** A planted rental threshold (0.71 instead of 0.7) passed all 112 golden walks, which have only 3 stake-8 seeds. The workers' 200k stake-8 walks caught it with 36,871 differences. So the random-seed half of the scenario is load-bearing. **Verified.**
- **An FFI error at top level can segfault the host.** When a script dies with an error, `lua_close` runs the `ffi.gc(bh_new(), bh_free)` finalizer. Sometimes the clib is unloaded by then: the process exits 139 and the buffered stdout is lost. **Verified** under the system luajit with a planted error. The test now runs each shop group under `pcall` and ends with `os.exit`. T-343 should free contexts explicitly, or keep the library alive past its contexts.
- **The `(x = f()) != x` NaN test is undefined behaviour in C.** It has no sequence point. gcc warned (`-Wsequence-point`) and the code now uses `isnan(x = f())`. **Verified**: the build is clean.
- **Mutations the unit test cannot see:** `poll <= 0.7` → `< 0.7` (sticker band), get_pack's `it >= poll and it - w <= poll` → `it > poll`, and the Black Hole gate overriding a Soul hit. The first two differ only when a draw is exactly equal to the bound. The third needs two draws over 0.997 in a row on one card (~1e-5). The code keeps vanilla's form. Planted bugs that were caught: skipped row release, skipped pack release, the tag-pack/Boss-shop order, rarity, the Illusion edition, the seal band, the Standard edition `_mod`, the rental stream key, perishable compat, the Omen Globe threshold, Telescope's card index, the Soul gate ignoring a used Soul, the Black Hole gate ignoring a used Black Hole, a banned forced key, the forced first Buffoon when banned, the front count, and reroll release.
- **Not modelled**, because no output reads it or the walk never holds it: To Do List's `to_do` draw, Showman, tags held into the shop (`store_joker_create/modify`) and the tutorial `forced_shop`. The `predict` contract excludes the same set. **UNVERIFIED** for runs that hold those.
- The synthetic test seeds first came from a period-34 formula, so there were only 34 distinct seeds. The Black Hole gate then never fired and hid a mutation. They now come from an LCG. T-341's group 4 uses a similar formula, `(i*7 + j*13 + i*j) % 34`, plus a suffix on every 10th seed, so it covers fewer distinct seeds than its count suggests. **UNVERIFIED** how many. I left it unchanged, since T-341's rig diff covers 1M real seeds.
